# LFM3 Workspace v0.1.0

**A fully local, chat-first cowork harness for Liquid AI's LFM3 family — Rust, React, Tauri 2, and pinned llama.cpp.**

Everything runs on your own machine: no account, no cloud calls, no telemetry. Four local models cover the work — LFM3-1.7B acts and writes, LFM3-VL-2B looks at images, LFM3-Audio-2B hears and speaks, and d1-2B routes each turn and checks evidence. The harness shows every tool call, keeps writes behind an exact-diff approval, and never reports unverified work as finished.

## What is in this build

- **32,000-token context for the acting model.** The text model is now served with `-c 32000` (previously 8,192), and the chat history budget rises to 96,000 characters across the newest 240 messages, leaving room for tool output and the reply.
- **Runtime included, weights excluded.** Both downloads carry the pinned llama.cpp **b11960 / v0.8.0** runtime and mission definitions. No GGUF file is inside either archive, which keeps the installer at about 15 MB instead of several GB.
- **In-app model download.** The **Models** menu lists all four roles with **Loaded**, **Installed**, or **Missing** state. A download starts only on an explicit click, streams to a `.part` file with visible progress, verifies the published byte length and SHA-256, then moves the file into the models folder. Nothing fetches models in the background.
- **Manual models are detected.** Weights placed in the models folder by hand are found on the next launch or with **Reload installed models**; the folder path is shown at the top of the Models menu.
- **Local chat with guardrails.** Streamed answers, native or fenced tool calls, workspace-confined files (`list_files`, `read_file`, `search_files`, `related_files`, `write_file`, `edit_file`), a decision route, an evidence gate, and a Stop control that cancels the stream and any pending approval.
- **Verified tasks stay separate.** Anything that must be machine-certified runs as a frozen-acceptance mission; a chat message can never satisfy a mission check.

**Windows installer contents:** the desktop application, React UI, mission definitions, and the CPU llama.cpp runtime (`llama-server.exe`, `llama-tts.exe`, and their DLLs), staged as bundled resources. CPU only (`-ngl 0`); no CUDA or Vulkan build is included.

The desktop shell is Windows-only because it owns child processes through a Windows Job Object; on Linux the supported surface is the CLI.

## Install on Windows

1. Download `LFM3.Workspace_0.1.0_x64-setup.exe` and run it. The installer is unsigned, so SmartScreen may ask you to choose **More info → Run anyway**.
2. Launch **LFM3 Workspace**. The app opens on chat and looks for a bundled runtime and any installed weights.
3. Open the **Models** menu next to the model chip (or the header **Models** button). The menu shows the models folder and each role's state.
4. Click **Download** for the roles you want. Sizes and checksums are pinned:
   - **Text and agent** — `LFM3-1.7B-Q4_K_M.gguf`, 1.10 GB
   - **Vision** — `LFM3-VL-2B-QAD-Q4_0.gguf` + `mmproj-LFM3-VL-2B-Q8_0.gguf`, 1.25 GB
   - **Voice in and out** — `LFM3-Audio-2B-Q4_K_M.gguf` + `mmproj-LFM3-Audio-2B-Q8_0.gguf`, 1.40 GB
   - **Decision** — `d1-2B-Q4_K_M.gguf`, 1.10 GB
   All four together are about 4.9 GB. The text role is the minimum for chat; vision, voice, and routing light up as their files arrive.
5. Choose a folder with the folder chip, then ask a question or attach an image. **Voice replies** turns on local speech output when the audio pair is installed.

### Where models go

The default models folder is `%LOCALAPPDATA%\LFM3Harness\models`. Downloads are placed in one subfolder per repository, for example:

```
%LOCALAPPDATA%\LFM3Harness\models\LFM3-1.7B-GGUF\LFM3-1.7B-Q4_K_M.gguf
%LOCALAPPDATA%\LFM3Harness\models\LFM3-VL-2B-GGUF\LFM3-VL-2B-QAD-Q4_0.gguf
```

You can also copy the GGUF files there yourself, or set `LFM3_MODELS_DIR` to an existing weights folder. The app searches that folder up to six levels deep for a file whose name contains the role token, so the exact subfolder name is flexible; the file names above are the pinned ones. After a manual copy, open the Models menu and choose **Reload installed models**.

## Install on Linux

```bash
tar -xzf LFM3-Workspace_0.1.0_linux-x64_cli.tar.gz
cd LFM3-Workspace-linux-x64
mkdir -p models && cp /path/to/*.gguf models/
./run.sh doctor
./run.sh models --probe
./run.sh run --mission desk_task \
  --input ../tests/fixtures/desk_task/basic.json \
  --workspace ./workspace
```

`run.sh` points `LFM3_LLAMA_SERVER` at the bundled `tools/llama/llama-server` and `LFM3_MODELS_DIR` at `models/` when those exist. The Linux build has no model downloader; supply the same pinned GGUF files described above. The archive was built on Ubuntu 22.04 x64.

## Requirements

- Windows 10 or 11 x64, or Linux x86_64 with a recent glibc.
- CPU inference; no GPU is required or configured.
- 8 GB of RAM for chat with the text role, more when the vision, voice, and router models run alongside it.
- About 4.9 GB of disk for all four roles, plus the models folder you work in.

## Known limitations

- The Windows installer is unsigned, so SmartScreen warns on first run.
- The runtime is CPU-only; expect slower turns than a GPU build.
- The desktop shell and its model downloader are Windows-only. The Linux release is the headless CLI, with weights supplied separately.
- Three semantic missions remain `human_review_only`; only `desk_task` has an end-to-end real-model acceptance.
